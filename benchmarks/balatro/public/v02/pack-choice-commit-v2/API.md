# PC2_MODEL — public protocol v1

Global `PC2_MODEL` exports `new`, `begin`, `register`, `commit`, `close`, `settle`, `view`. Global `PC2_STATUS()` returns the detached `view` of the live adapter ledger and has no effects. Core states are opaque, independent and need no game globals. No internal layout is prescribed.

All identifiers are nonempty ASCII strings, at most 96 characters, from letters, digits, `_ . : -`. Validate argument domains first; invalid returns exactly `{ok=false,code='INVALID'}`. Every other error has the same two fields with its specified code. Errors leave the entire state unchanged. All returned tables must be detached.

- `begin(state,session)`: create an open session with two choices and no previews; return `{ok=true,created=true}`. Same existing ID, even closed, returns `{ok=true,created=false}` without resetting it.
- `register(state,session,preview,reward)`: reward is exactly 3, 5 or 7. Session must exist or `SESSION_MISSING`. A previously registered same preview globally, same session and reward returns `{ok=true,created=false}` even after closure; different session/reward returns `PREVIEW_CONFLICT`. For a new preview, closed session or any prior commit in that session returns `REGISTRATION_CLOSED`; already three previews returns `PREVIEW_LIMIT`. Otherwise register and return `{ok=true,created=true}`.
- `commit(state,session,preview,commit_id)`: globally unique commit ID identifies this acquisition. If already accepted with identical session/preview, return `{ok=true,new=false,ticket=commit_id,amount=<original reward>}` without changes, even if closed/settled. Conflicting reuse returns `COMMIT_CONFLICT`. Then require an existing session (`SESSION_MISSING`), open session (`SESSION_CLOSED`), all three previews registered (`PREVIEWS_INCOMPLETE`), this preview registered to that session (`PREVIEW_MISSING`), not selected (`PREVIEW_COMMITTED`), and remaining choices (`CHOICES_EXHAUSTED`), in that order. Success marks only that preview selected, decrements remaining, creates one pending ticket and returns `{ok=true,new=true,ticket=commit_id,amount=<reward>}`. A rejected ID remains available for a later legal request.
- `close(state,session)`: existing session becomes closed; repeats are harmless; both return `{ok=true}`. Unknown session returns `SESSION_MISSING`. Preserve tickets, selected previews and paid total. No unselected reward is created.
- `settle(state,ticket)`: unknown ticket returns `TICKET_MISSING`. Pending ticket becomes settled, increments paid total by its reward and returns `{ok=true,amount=<reward>,already=false}`. A settled ticket returns `{ok=true,amount=0,already=true}`. Settlement is legal after closure. This is an in-process at-most-once payout claim, not a crash transaction guarantee for arbitrary external side effects.
- `view(state)`: detached `{sessions=[...],tickets=[...],paid=<sum>}`. Sessions sorted by ID contain exactly `{id,closed,remaining,previews=[{id,reward,selected},...]}` with previews sorted by ID. Tickets sorted by ID contain exactly `{id,session,preview,reward,settled}`. Empty collections are empty lists. Repeated reads are pure.

Native session identity can use the physical Booster's `sort_id`; preview identity uses the chosen physical Joker's `sort_id`, never its mutable row index. `SMODS.Booster.create_card` receives the physical Booster and original creation index; native add-to-deck is the acquisition boundary. Route native pack closure to `close` and deferred reward callbacks to `settle`. Preserve original lifecycle calls, arguments, return values and exceptions. Schedule a payout only for a new accepted commit; apply the returned settlement amount once. Native observations and protocol tests are separate evidence layers.
