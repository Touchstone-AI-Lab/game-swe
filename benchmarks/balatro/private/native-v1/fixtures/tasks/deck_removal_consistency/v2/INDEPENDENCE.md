# M2 v2 independence and provenance

The target set is physical identity across a real highlighted batch; committing that set must agree with area membership, persistent registry/counts, subsequent refill and a later independent removal. v1 already supported one/two nonadjacent removals. v2 adds a mixed-property batch of four, an identical-face survivor and repeated three/one removal across a blind boundary, with two related starter regressions. The change is a coherent selection-to-persistent-destruction repair, not a renamed mutation or a claim based on file/line counts.

It is distinct from consumable generation/capacity, reversible hand limits, owned shop rules, saved charge, adjacency, wear, pack commitment and seeded rewards. No natural reordering assumption, save restoration, special enhancement or destruction-replacement effect is used. This is an authored exercise against pinned native/SMODS APIs, not an upstream historical bug. Medium is a design intent, unmeasured by models.

Only public CONTRACT, generic README, package manifest and starter are exportable. Private rule matrix, fixture, passive observer, scenario, controls and engine evidence remain operator assets.
