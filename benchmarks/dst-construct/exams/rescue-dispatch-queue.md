# Lease-based rescue dispatch queue

## Background and goal

In a multiplayer world several low-health, downed or trapped players may appear at the same time. Rescue requests must queue stably, one volunteer must not hold several tasks at the same time, and the same target must not be assigned to several people. After a volunteer disconnects or stops sending heartbeats, the unresolved task should automatically return to the queue.

Implement a plain Lua dispatcher, plus a server-side component and a read-only replica.

## Core semantics

1. Time must be finite, non-negative and must not move the global clock backwards. Player updates carry a monotonic `revision`; stale updates have no side effects.
2. `record` contains at least `id`, `revision`, `connected`, `alive`, `health_percent`; an invalid or non-finite health ratio must be rejected.
3. Incidents are ordered by effective severity descending, creation time ascending, then target ID in lexicographic order. Waiting-time aging is determined by `options.aging_interval` and must not depend on how often `tick` is called.
4. One helper holds at most one live lease, and one target has at most one helper. Lease IDs are generated by an internal stable sequence.
5. `volunteer` must first deduplicate by helper/request ID, and then create a lease for the current highest-priority unassigned incident.
6. Only a live lease belonging to the matching helper can be targeted by heartbeat or complete. A heartbeat sets the expiry time to a deterministic new boundary; reaching the boundary counts as expired.
7. Expiry, helper disconnect or helper death releases the helper and requeues the unresolved target exactly once. Target recovery, death, disconnect or cancel ends the incident.
8. `snapshot` is stably ordered by queue and by lease and does not expose personal request history; `save/load` must preserve the idempotency history and the lease boundaries.

## Return values and data shapes

The hidden tests depend only on the following public shapes:

- `options.lease_ttl` is the lease duration (seconds), `options.aging_interval` is the waiting-time aging interval, and `options.recovery_threshold` is the recovery threshold, which defaults to `0.75` when not configured.
- A player with `health_percent >= recovery_threshold` counts as recovered: such a player cannot become a rescue target, and an existing incident ends accordingly; rescue can be requested for a living, connected player below the threshold.
- `update_player` returns `false` when rejected and any non-`false` value on success.
- `request` returns a new table containing a boolean `ok` and `target_id`; a retry with the same `request_id` returns the first result (including the first `target_id`).
- `volunteer` returns a new table containing `ok`; on success it also contains `lease_id`, `target_id` and `expires_at = now + lease_ttl`. A retry with the same helper and `request_id` returns the original lease.
- `heartbeat` and `complete` return a table containing a boolean `ok`. The lease has expired when `now >= expires_at`.
- The top level of `snapshot(now)` contains the array `queue` (incidents that have no helper assigned yet) and the array `leases` (live leases).
- `UpdatePlayer` and `Request` of the world component return `false` when rejected; `Volunteer` returns a table containing `ok` and `target_id`, where `target_id` is the `userid` of the target player.

## DST integration

- The master simulation world component reads the real state from the entity's `health` and `Transform`; client coordinates or severity may only serve as non-authoritative hints and must not override server-side observation.
- Listen for `ms_playerjoined`, `ms_playerleft` and the player's `healthdelta`, `death`, `respawnfromghost`, `onremove`.
- The RPC handler obtains the helper identity from `player.userid` and accepts only request/lease identifiers.
- Use `DoPeriodicTask` to advance expiry; when the component is removed, cancel the task and unregister all events.
- Use `AddReplicableComponent` and net variables to publish a compact, read-only task state without private request history.
- Persist the dispatcher through `OnSave/OnLoad`.

## Base-game API contract

The base-game shapes of player health and world events are as follows:

```lua
local health_percent = player.components.health:GetPercent()
local x, y, z = player.Transform:GetWorldPosition()

TheWorld:ListenForEvent("ms_playerjoined", on_player_joined)
TheWorld:ListenForEvent("ms_playerleft", on_player_left)
player:ListenForEvent("healthdelta", on_health_delta) -- data.oldpercent, data.newpercent
player:ListenForEvent("death", on_death)
player:ListenForEvent("respawnfromghost", on_respawn)
player:ListenForEvent("onremove", on_remove)
```

`EntityScript:DoPeriodicTask(period, fn, initialdelay, ...)` returns a task; on cleanup, check for nil first and then call `task:Cancel()`. Unregistering a listener must use the same callback and source as at registration.

The replica and the netvar must be set up before the client early return:

```lua
inst._rescue_state = net_string(inst.GUID, "rescuedispatch.state", "rescuedispatchdirty")
AddReplicableComponent("rescuedispatch")
```

The server-side component must expose `UpdatePlayer(player)`, `Request(request_id, target)`, `Volunteer(request_id, helper)`, `Heartbeat(lease_id, helper)` and `Tick(now)`. The first argument of an RPC handler is the real `player` passed in by the base-game framework; the identity is read from `player.userid`.

## Acceptance

- Ordering is not affected by insertion order or by `pairs` order.
- A helper/target never has two live leases at the same time.
- A late heartbeat must not revive an expired lease.
- Disconnect, death, recovery and reload all correctly release or keep tasks.
- The headless dedicated server test creates server entities with the base-game `health` component and asserts the deterministic lease driven by real health values as well as the `OnSave/OnLoad` round trip; event listeners, network state and cleanup are covered by static integration checks.
- The static checks require that the non-blank, non-comment code of all submitted Lua files totals at least 260 lines, and that the base-game API wiring listed in this document is satisfied.

Only base-game APIs and assets may be used, and authoritative dispatch must not be placed in the replica.
