# Rhenium GMod benchmark pack

- `catalog.json` is the machine-readable Addon catalog and `benchmark.json` selects the unified Garry's Mod plugin.
- `private/tasks/<task-id>/hidden/` owns plain-Lua behavioral assertions.
- `private/tasks/<task-id>/integration/` owns adapter assertions.
- `private/tasks/<task-id>/server/` owns the Dedicated Server addon and Phase A/B suite.
- `private/tasks/<task-id>/references/` and `mutations.json` are evaluator-development extensions owned by the same task.
- `private/tasks/<task-id>/contract-traceability.json` privately maps every scored case to a numbered public clause without exposing case names.
- `exams/<task-id>.md` is the sole canonical public exam and is bound by path, digest, and explicit evidence.
- `sources/<task-id>.json` records Workshop feature-existence evidence and the no-code/no-assets-copy boundary.
- `private/harbor/<task-id>/` is the task's [Harbor 1.4 package](private/harbor/README.md), generated by `private/harbor/scripts/materialize.py`.
- `private/runtime/gmod-harbor-runtime/` is the build context of the local verifier image that wraps an operator-retained pinned Linux Dedicated Server.

The formal catalog contains exactly five Workshop-derived clean-room tasks: Prop ownership/quota, staged three-point Prop alignment, persistent loadout profiles, a Hot Object round controller, and a contraption blueprint duplicator. Every task owns two structurally distinct references, a mutation matrix, a private public-contract traceability map, and a two-process Dedicated Server suite.

Catalog version `2.1.0` was the Gate 6.7 public-contract baseline; `2.2.0` translates every canonical exam, and the Harbor instruction header, from Chinese to English without changing any clause, interface, required file or assertion, so each exam heading now matches the English catalog title. Each canonical exam has numbered public clauses, at least eight bilingual requirements, five bilingual API-use obligations, and five bilingual acceptance outcomes. A changed exam must receive a new digest, and any scored case without a valid public-clause mapping fails validation.

GMod-specific integration, server, reference, and mutation assets extend the common task layout; they do not replace the common catalog, exam, hidden, server, prepare, score, or anonymous-attempt responsibilities. Evaluator-generated runs, logs, and server clones stay below Rhenium state; a prepared attempt is written only to the operator-selected public destination.

References are validation gold controls and mutations are evaluator-regression
inputs. Neither participates in dynamic submission scoring, and neither is
packaged into the core or plugin wheel or copied to an anonymous attempt.

`rhenium-gmod-v2` names the catalog identity; it is not the semantic-version major. The current catalog, pack, and all five task/runtime contracts are `2.2.0`, while the Python package has its own independent release version. The catalog pins App ID 4020 and stable build 23150012 for Windows; the additive `runtime.linux_build_id` pins Linux separately to the same build without changing any task semantics. `benchmark.json` supplies the game-neutral schema-v2 pack identity.

Discover the pack with `RHENIUM_BENCHMARK_PATH="$PWD/benchmarks" rhenium tasks --game garrys-mod --pack addons`. On Windows or Linux x86_64, configure `RHENIUM_PLUGIN_GMOD_SERVER_ROOT` and a global timeout ceiling of at least the task timeout; Rhenium state and the server must share a filesystem (NTFS on Windows) because per-run views use hard links. Without the pinned native Dedicated Server, the reduced `core` profile may run but a complete score is impossible. Windows Job Objects and Linux process groups do not make a same-Lua-state private suite secret from a malicious Addon. See [Linux setup and control evidence](../../docs/games/garrys-mod.md#native-linux-runtime).
