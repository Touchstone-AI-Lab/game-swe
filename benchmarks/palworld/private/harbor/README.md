# Palworld Harbor task suite

This directory exports ten Palworld Rhenium generation tasks as
independent [Harbor 1.4 packages](https://www.harborframework.com/docs/tasks).
Catalog 1.1.0 originally added
five advanced tasks in the same `Info.json` plus UE4SS Lua format; see the
[exam index](../../exams/README.md) and [new control matrix](../../validation/advanced-controls.md).

Every task has the standard Harbor layout:

```text
task.toml
instruction.md
environment/Dockerfile
environment/mod/README.md
tests/Dockerfile
tests/test.sh
solution/reference/...
solution/solve.sh
```

This is a public repository: `tests/` and `solution/reference/` are open
benchmark assets, not confidential source. They are isolated at execution time.
The evaluated agent receives only the empty `environment/mod/` starter; after
the agent phase, Harbor supplies `tests/` to a separate verifier container. The
`oracle` control alone uses `solution/solve.sh` to copy
`solution/reference/` into `/app/mod`.

The files under `solution/reference/` are portable verifier fixtures. A passing
fixture demonstrates that the Lua 5.4 and simulated UE4SS checks have a known
passing input; it is not a claim that the fixture has passed in a real Palworld
process.

## Verification boundary

The portable verifier fails closed and awards a binary reward. It checks required
files, a server-capable Palworld manifest, Lua 5.4 syntax, implementation depth,
UE4SS integration contracts, the complete pure-Lua behavior suite, and a restricted
simulated UE4SS server contract. Candidate Lua cannot read arbitrary host files or
access Python objects through the behavior harness.

The Linux Harbor container does **not** boot the Windows Palworld dedicated server.
Accordingly, its result records `real_palworld_server_ran=false`, and a Harbor pass
must not be presented as real-engine evidence. Use the existing Rhenium `full`
profile and a prepared disposable server described in `docs/games/palworld.md` for
that evidence.

## Versions and regeneration

- Format reference: Harbor schema 1.4 at revision
  `9a2e3b135cc8fb1e41131020f83370cb2f12ae93`.
- The Rhenium catalog keeps the stable ID `rhenium-palworld-v1` and advances to
  1.1.0 for five additional task identities. The original five entries remain
  unchanged; evaluator weights and full-profile requirements are unchanged.
- Each newly introduced Harbor package starts at version 1.0.0.

Canonical task content remains in `exams/`, `hidden/`, `server/`, and
`fixed-v1.json`. After an intentional authoring change, regenerate duplicated
Harbor assets from the repository root:

```sh
python benchmarks/palworld/private/harbor/scripts/materialize.py
```

After Docker and Harbor are available, run the oracle and nop controls with:

```sh
harbor run --path benchmarks/palworld/private/harbor/guild-storage-ledger --agent oracle -y
harbor run --path benchmarks/palworld/private/harbor/guild-storage-ledger --agent nop -y
```

These jobs could not be built when the export was authored: both Dockerfiles
pinned a `bash` package revision that the dated Debian snapshot does not contain,
and the agent image smoke-tested `mini --version`, which mini-swe-agent 2.4.6
rejects. With those two build defects fixed, Harbor CLI 0.23.0 on Linux x86_64
(2026-09-21) scored reward 1.0 for the `oracle` agent and 0.0 for the `nop` agent
on all ten tasks. That is evidence for the portable Lua 5.4 verifier only; a
real Palworld dedicated server still does not run in these containers.

On Windows systems whose Python default encoding is not UTF-8, set
`PYTHONUTF8=1` before invoking Harbor so its task loader can read the UTF-8 task
files: `instruction.md` is English since catalog 1.2.0, but each `tests/spec.json`
still carries the catalog's Chinese strings. This is unnecessary on the UTF-8 Linux
task container.

The recorded direct-verifier controls and known limitations are in
`validation/README.md`.

## Catalog 2.0.0

The active export replaces the Palbox and damage construct tasks with
`base-containment-mincut` and `guild-draft-canonical-order`. Both new Harbor
packages start at 1.0.0. Their empty starters, public contracts, duplicated tests
and reference fixtures are generated by the same materializer. The other eight
packages are unchanged. Retired package directories remain historical assets;
select only IDs registered in the current catalog when scheduling Harbor jobs.

The portable verifier still records `real_palworld_server_ran=false`. Native
Linux real-engine controls run separately through the Rhenium full evaluator;
see [Linux controls](../../validation/linux-controls.md). The previous ten-task
Harbor oracle/nop results above describe catalog 1.x, not the two new packages.
