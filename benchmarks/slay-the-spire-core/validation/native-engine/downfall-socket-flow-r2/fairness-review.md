# Guardian campfire selection author review

The r1 formal controls were rejected because software-renderer oversubscription dropped native input under a two-CPU quota. This r2 revision pins LP_NUM_THREADS=2 with the same two-CPU quota; unasserted original observations reproduce in both orders. Prompt, Probe, expectations and repair sources are byte-identical to the first candidate. Every author variant is replayed under the formal CPU quota. The rejected records remain preserved.

Original MIT Downfall commit030ff7d4a7419a3e21c3075661550b1b479f3502; no injected defects. Twelve unasserted real-game scenes agree in both orders before assertions and repair runs. The first draft lost its initial physical click to native window focus; a retry of the same OS click corrected that fixture. No failed setup is counted as an upstream defect. The second draft reached a genuine uncaught SocketGemEffect.update ClassCastException after cancelling gem choice and using the native Smith action on Strike_Red. Its game crash screen was explicitly stopped and retained as observation evidence, not represented as a complete benchmark run.

Each retained scene constructs a fresh native Guardian, Exordium and RestRoom. A public master deck contains real red/green gems, a PrismaticBeam with its constructor-provided sockets, and an ordinary upgradable Strike. The real campfire enhance option is pressed by java.awt.Robot. Card and confirm buttons receive actual OS mouse events; Escape receives an actual key press. The follow-up Smith uses the ordinary public SmithOption.useOption with a valid upgradable deck, followed by native OS-driven selection/confirmation. The successful Smith controls use exactly that same route. No selectedCards, internal timer, patch flag, private collection or expected result is injected. Phase driving reads public native visible grid membership, not the mod's internal selection-state flags.

The harness adds one exception boundary around SocketGemEffect.update. It does nothing to successful calls; only after an actual Throwable has escaped does it record that exception and mark the failed effect done so remaining observations can run. This contains the native crash already recorded without that boundary. Every caught exception fails its scene even if the independent Smith action can then complete. The other cancelled-Smith case selects a real Guardian card and demonstrates incorrect redirection and an unupgraded card without any exception. These are two outcomes of the same abandoned selection ownership defect, not two separately counted defects.

Thirteen clauses include six controls. Exact native matrix: base6,gold13,alternative13,back-only10,retirement-only9. Each isolated repair flips exactly its own failed group and preserves every control. Expectations concern actual deck/gem consumption, the displayed target group, successful native upgrades, screens and exceptions. They do not assert the mod's booleans, a particular cancellation object, timer, method structure or callback trace. Intermediate event logs and source hypotheses are not scored.

Gold handles Back once in the prefix and prevents the same input from cancelling the newly opened gem grid; cancelling the initial gem choice immediately clears and retires that effect. The alternative snapshots the original cancellation context, lets the vanilla button perform ordinary cancellation, then restores the gem screen in a postfix when appropriate. It records abandonment on the effect and retires through its next native update. These structurally different complete implementations both pass every native clause. The four Back scenarios include changing to the other gem and completing insertion, preventing a superficial UI-only repair from passing.

The task concerns ordinary sequential campfire operations and is distinct from the existing Stasis lifecycle task, the retired card-transfer/hand-selection library candidates, the retired Packmaster campfire-button refresh and BaseMod phase dispatch. There is no new requirement for arbitrary invalid gems, controller timing, concurrent room changes, capacity expansion or private field representation. This author review establishes satisfiability and independence, not difficulty. Formal nop/oracle and image/archive audits are still required.
